# 实施计划

采用 Vite、原生 TypeScript 和 CSS 构建静态网站，以最少依赖实现首页、筛选和活动详情。招聘数据保存在仓库 JSON 中，Node 脚本负责校验、筛选、去重和抓取，GitHub Actions 负责候选内容审核与 GitHub Pages 发布。

## 范围

- 包含：学生端首页、活动详情、搜索筛选、响应式与无障碍、示例数据、数据校验、专业匹配、去重、GitHub Issue Forms、来源抓取框架、审核 Pull Request 工作流、Pages 部署。
- 不包含：学生账号、收藏、通知、简历投递、企业自助发布、付费数据库、绕过登录或验证码。

## 执行项

- [ ] 1. 初始化 Vite + TypeScript 项目，配置 `base`、ESLint、类型检查、Vitest 和生产构建命令；验证：空项目 lint、类型检查、测试和构建全部通过。
- [ ] 2. 在 `src/data/types.ts`、`src/data/validate.ts` 和 `data/events.json` 定义活动与岗位模型、校验规则及可识别的示例数据；验证：合法样例通过，缺失标题、日期或来源链接的样例失败。
- [ ] 3. 在 `src/domain/` 实现时间排序、进行中优先、专业相关性筛选和去重函数；验证：为目标专业、不限专业、无关专业、跨日活动和重复来源编写单元测试。
- [ ] 4. 在 `src/ui/` 实现已确认的首页结构、完整日期时间轴、搜索和专业/类型筛选；验证：筛选组合、空状态和清除筛选可用。
- [ ] 5. 实现滚动位置渐变、悬停/键盘聚焦信息框、浅深色主题和移动端布局；验证：中心内容保持完整清晰，减弱动效和不支持滚动动画时回退为完整对比度。
- [ ] 6. 实现活动详情视图，展示企业、岗位、薪酬、学历、地点、网申入口、来源与核验提示；验证：缺失字段显示“未公布”，外部链接协议受限于 `https` 或明确允许的 `http` 来源。
- [ ] 7. 添加“手动录入”和“提交来源链接”GitHub Issue Forms，并实现将表单内容转换为候选 JSON 的脚本；验证：格式错误只产生校验报告，不修改已发布数据。
- [ ] 8. 在 `scripts/scrapers/` 建立独立来源适配器接口，先实现可稳定访问的福建就业网适配器并为其他来源保留明确失败状态；验证：使用本地页面样本测试解析，不在测试中请求实时网站。
- [ ] 9. 添加抓取候选 Pull Request、构建部署和失效链接检查工作流；验证：候选数据只能通过审核合并发布，GitHub Pages 构建产物可在仓库子路径正常访问。
- [ ] 10. 执行完整质量检查与浏览器验收；验证：lint、类型检查、单元测试、生产构建、链接检查、键盘操作、移动端与桌面端检查全部通过且无跳过项。

## 假设

- 仓库最终为公开仓库，默认分支为 `main`。
- 第一版详情采用站内详情视图，不引入客户端路由库。
- 初始自动抓取仅承诺一个已验证来源，其余来源逐站适配，失败时仍可人工录入。
- 公众号链接仅作为来源保存，由管理员人工补全结构化字段。

## 开放问题

无阻塞问题。GitHub 仓库名称与 Pages 最终网址在发布阶段确定，不影响本地开发。
